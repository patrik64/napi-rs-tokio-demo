# napi-rs + tokio in SvelteKit

A SvelteKit 3 app that calls async Rust. The Rust side is a [napi-rs](https://napi.rs) addon built
with the `tokio_rt` feature, so every exported `async fn` is a JavaScript function that returns a
promise, run by a tokio runtime living inside the Node process.

The page is a set of live demos. Each one shows its own source next to it.

| Demo | What it shows | Rust | Endpoint |
| --- | --- | --- | --- |
| Promises | `async fn` → promise, `Err` → rejection, `tokio::time::timeout` | `native/src/delay.rs` | `api/delay` |
| Blocking work | Sync export vs. `async fn` vs. `spawn_blocking`, and what each one blocks | `native/src/cpu.rs` | `api/primes` |
| Concurrency | `JoinSet` and `Semaphore` | `native/src/fan_out.rs` | `api/fan-out` |
| Parallelism | CPU-bound tasks spreading across every worker by work stealing, with and without `yield_now` | `native/src/parallel.rs` | `api/parallel` |
| Callbacks | `mpsc`, `ThreadsafeFunction`, `CancellationToken`, relayed as server-sent events | `native/src/stream.rs` | `api/stream` |
| Network I/O | `tokio::net` lookups and TCP connects with per-attempt timeouts | `native/src/probe.rs` | `api/probe` |
| Metrics | A sync export reading tokio's runtime metrics, feeding the monitor bar | `native/src/runtime.rs` | `api/pulse` |

## Running it

You need Node 22.17 or newer, pnpm, and a stable Rust toolchain.

```sh
pnpm install
pnpm dev        # compiles the addon, then starts Vite
```

Other scripts:

```sh
pnpm native     # compile the Rust addon only
pnpm build      # compile the addon and build the app with adapter-node
pnpm start      # run the production build (node build)
pnpm check      # type-check
```

Node can't reload a native addon it has already loaded. After changing Rust code, stop the dev
server and run `pnpm dev` again.

## How it fits together

```
native/                  the Rust crate, also a pnpm workspace package (@napi-tokio/native)
  Cargo.toml             napi with features = ["napi9", "tokio_rt"]
  src/lib.rs             builds the tokio runtime when the addon loads
  src/*.rs               one module per demo
  index.js, index.d.ts   generated by `napi build`: the loader and its TypeScript types
src/
  routes/api/*/+server.ts   endpoints that import and await the Rust functions
  routes/+page.svelte       the page
  lib/demos/                one component per demo
  lib/components/           the monitor bar, code tabs, shared controls
  lib/server/               event-loop lag measurement, SSE helper, source highlighting
```

The app depends on the addon as `"@napi-tokio/native": "workspace:*"`. Server code imports it like
any other package, and components import only its types.

## Deploying

The addon is compiled for the machine that builds it. `tokio-native.<platform>.node` is not
portable, so build on the same OS and architecture you deploy to, or cross-compile with
`napi build --target`. The production server needs `build/`, `node_modules/` and `native/` (for
`index.js` and the `.node` file) at runtime.
